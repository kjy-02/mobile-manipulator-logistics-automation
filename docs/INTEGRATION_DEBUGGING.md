# 모바일 매니퓰레이터 주행·파지 통합

SCOUT 2.0이 실내 픽업존까지 이동하면 xArm5가 상자를 집어 차량 측면 트레이에 싣는 시스템을 만들었다. 지도 작성과 실차 시험, 최종 시연은 모두 실내에서 진행했다. 3인 팀에서 3D LiDAR 지도 작성, HDL Localization 설정, DWA 수정과 실차 통합 시험을 맡았다. xArm5 조작부는 팀원이 담당했다.

## 1. 픽업존에 도착해도 파지가 시작되지 않았다

픽업존에 도착한 뒤 DWA의 전진·회전 명령은 0이었고 `finish_flag=True`도 계속 들어왔다. 그런데 주행 연결 프로그램이 종료되지 않아 다음 단계인 YOLO와 xArm5가 실행되지 않았다.

코드를 확인해 보니 연결 프로그램은 DWA의 완료 신호를 받은 뒤에도 TF가 최근에 갱신됐는지, 목표까지의 거리가 0.5 m 이내인지, 방향 오차가 0.1 rad 이내인지 별도로 검사하고 있었다. 두 프로그램의 도착 판정 기준이 달라 DWA가 도착을 알린 뒤에도 전환이 막힐 수 있었다. 당시 어느 조건에서 막혔는지는 확인하지 못했다.

`run_goal_navigation.py`의 `arrived()`에서 추가 검사를 제거하고, DWA의 `finish_flag`를 단계 전환 기준으로 사용했다. 완료 신호가 들어오면 차량을 정지시키고 DWA를 종료한 뒤 YOLO와 xArm5를 실행하도록 연결했다. 수정 후 실차에서 주행이 끝나고 팔이 초기 자세까지 이동하는 것을 확인했다.

## 2. RGB 영상이 끊겨 팔이 목표 좌표를 받지 못했다

xArm5는 초기 자세까지 이동했지만 `camera_link`에서 `ap_target`으로 이어지는 TF를 기다리다 시간 초과가 났다. RGB와 깊이 영상 모두 첫 프레임을 받았다는 로그가 있었지만, 실제 수신 주기를 확인하니 깊이 영상은 약 24~30 Hz로 들어왔고 RGB에는 `no new messages`가 표시됐다. 카메라 전송 관련 경고도 반복됐다.

카메라 입력, YOLO 검출, 목표 좌표 발행, 팔의 좌표 수신 순서로 점검했다. 카메라 TF가 있어도 RGB 영상이 끊기면 YOLO가 검출을 진행할 수 없어 목표 TF도 발행되지 않았다.

YOLO 화면 표시 여부, OpenCV 스레드 수, 처리 주기, 카메라 해상도와 프레임률을 바꿔가며 시험했다. YOLO를 끈 뒤 RGB가 다시 들어온 경우도 있었지만, YOLO를 실행하지 않은 상태에서도 끊김이 발생했다. USB 허브를 빼고 카메라를 노트북에 직접 연결해서도 시험했다.

최종 구성에서는 준비용 launch에서 카메라를 한 번만 실행하고, 사용하지 않는 RealSense L515의 포인트 클라우드 출력을 껐다. DWA에 필요한 LiDAR 포인트 클라우드와 객체 좌표 계산에 쓰는 깊이 영상은 유지했다. 비교 시험에서 바꿨던 해상도, 프레임률, OpenCV 스레드 수와 처리 주기는 기존 설정으로 돌렸다.

L515의 포인트 클라우드 출력을 끈 뒤 통합 실행에서 RGB 수신이 재개됐다. 충전기를 분리한 상태에서 간헐적인 프레임 저하가 관찰됐다. 전원 모드별로 같은 조건에서 프레임 수신 주기를 비교하지 않아 저하 원인은 확인하지 못했다.

## 3. 정지 상태에서 DWA의 최소 속도 후보가 최대 후보를 넘었다

목표 근처에서 차량 속도가 너무 낮아 최소 전진 속도를 0.1 m/s로 설정했다. 그런데 정지 상태에서는 가속도 제한을 적용한 최대 속도 후보가 0.05 m/s여서 최소 후보가 최대 후보보다 커졌다.

`calc_dynamic_window()`에서 최대 후보를 먼저 계산하고, 최소 후보가 그 값을 넘으면 최대 후보와 같은 값으로 제한했다. 변경 후 속도별 후보 범위와 C++ 빌드를 확인했다.

## 실내 통합 시연

차량이 픽업존에 접근해 정지한 뒤 xArm5가 빨강, 노랑, 파랑 상자를 차례로 집어 차량 측면 트레이에 실었다. 픽업존 접근부터 세 상자 적재까지 이어지는 동작을 실내에서 확인했다.
