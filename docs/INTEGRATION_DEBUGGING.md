# 주행과 파지 시스템을 연결하며 확인한 문제

지도 작성과 DWA 알고리즘 자체의 일반적인 결함 사례로 설명하지 않는다. 개별 기능을 연결했을 때 나타난 전환·입력 수신 문제를 다룬다.

근거는 2026-10-07 작업 로그, 현재 배포 코드, 이후 사용자 설명이다. 당시 실차 테스트는 사용자가 수행했고, 코드 점검·오프라인 검증·수정에는 Codex를 활용했다. 아래 결과는 시점별 확인 범위를 구분한다.

## 1. 도착했지만 파지 단계가 시작되지 않음

**현상**

DWA 전진·회전 명령이 0이고 `finish_flag=True`가 계속 들어왔지만 주행 연결 프로그램이 종료되지 않았다. 이후 실행할 YOLO·xArm 작업으로 넘어가지 못했다.

**확인한 구조**

DWA의 도착 완료 신호 외에 연결 프로그램에서도 TF 최신성, 거리 0.5 m 이내, 방향 오차 0.1 rad 이내를 재검사했다. 두 단계의 완료 판정 기준이 달랐다. 당시 어느 추가 조건이 실제로 실패했는지는 기록으로 확정하지 못했다.

**변경**

연결 프로그램의 추가 완료 검사를 제거하고 DWA의 `finish_flag`를 단계 전환 기준으로 사용했다. 이후 차량 정지 → DWA 종료 → 기존 YOLO/xArm launch 실행 순서로 연결했다.

**확인 결과와 범위**

10월 7일 후속 로그에서 DWA 종료 후 xArm 초기 자세까지 이어진 것을 확인했다. 그 시점에는 전체 파지·적재 성공을 확인하지 못했다. 현재 코드의 `run_goal_navigation.py`에도 동일한 `arrived()` 판정이 남아 있다.

이 변경은 완료 판정 책임을 DWA에 모은 것이다. 거리·방향·TF 및 완료 신호 나이에 대한 연결 프로그램의 독립 재검증은 현재 하지 않는다.

## 2. 팔 초기 자세 이후 목표 좌표를 받지 못함

**현상**

xArm은 초기 자세까지 이동했지만 `camera_link → ap_target`을 기다리다 시간 초과했다. RGB·깊이 첫 프레임 로그는 있었으나 실제 수신 주기를 확인하니 RGB는 `no new messages`, 깊이는 약 24~30 Hz였다. 카메라 전송 관련 경고도 반복됐다.

**진단**

TF 자체만 보기보다 카메라 입력 → YOLO 검출 → 목표 좌표 발행 → 팔의 좌표 수락 순서로 확인했다. 카메라 TF가 존재하더라도 RGB가 지속 수신되지 않으면 검출과 목표 TF 발행이 진행되지 않는다는 점을 확인했다.

YOLO 화면 표시, OpenCV 스레드 수, 처리 주기, 카메라 해상도·fps를 바꿔 비교했다. YOLO를 끈 뒤 RGB가 복구된 경우도 있었지만 YOLO 없이 끊긴 경우도 있어 추론 부하만으로 원인을 단정하지 않았다. USB 연결 구조도 확인하고 허브 대신 노트북에 직접 연결해 시험했다.

**최종 구성**

- 카메라는 준비 launch에서 한 번만 실행한다.
- 현재 작업에서 사용하지 않는 RealSense pointcloud 필터를 끈다. DWA의 LiDAR pointcloud와 YOLO용 깊이 영상은 유지한다.
- 비교 시험에 사용했던 해상도·fps, 스레드·주기 제한은 최종적으로 복원한다. 설정한 반복 주기를 실제 추론 fps로 표현하지 않는다.

**확인 결과와 범위**

**최종 결과 — 사용자 추가 확인(2026-10-29)**

> 통합 주행 코드 카메라 미송출 문제 해결 완료하였습니다.(L515 카메라의 포인트 클라우드 사용 안하니 작동, 카메라 프레임 떨어지는 상황은 조금씩있습니다.)

L515 카메라의 사용하지 않는 pointcloud 기능을 비활성화한 뒤, 통합 실행에서 카메라 미송출 문제를 해결했다. 이후 주행부터 파지·분류까지 야외 통합 시연을 진행했다. 간헐적인 카메라 프레임 저하는 남아 있다.

사용자 추가 관찰에 따르면 충전기를 연결한 상태에서는 괜찮았고 분리하면 프레임 저하가 나타났다. 사용자는 배터리 운용 시 저전력 모드 전환에 따른 현상으로 추정한다. 전원 모드·CPU 동작·프레임 수신 주기를 같은 조건에서 비교 측정한 결과는 아직 없으므로, 원인 추정으로 기록한다. 이는 해결된 카메라 미송출 문제와 구분한다.

10월 7일 로그에는 중간 시험과 최종 설정이 기록돼 있고, 해결 완료 여부와 남은 프레임 저하는 위 사용자 추가 설명으로 보완했다. USB 허브나 추론 부하를 단일 원인으로 확정한 것은 아니며, 처리량·프레임 저하율은 별도 측정값이 없다.

## 3. 실차 속도 설정을 조정하며 출발 후보 범위 보정

목표 근처에서 속도가 너무 낮아져 최소 속도를 0.1 m/s로 설정했다. 그러나 정지 상태에서 가속도 제한으로 계산한 최대 속도 후보는 0.05 m/s여서 최소 후보가 최대 후보를 넘었다.

최대 후보를 먼저 계산하고 최소 후보를 그 이하로 제한하도록 `calc_dynamic_window()`를 수정했다. 기록상 속도별 후보 범위와 C++ 타깃 빌드를 확인했다. 현재 배포 소스에도 해당 보정이 있다.

이는 설정 변경 시 가속도 제한과 후보 범위를 일관되게 유지하는 보정이다. 기존 DWA 전반에 문제가 있었다거나 차량 구동계의 저속 문제를 해결했다고 확대하지 않는다.

## 역할 설명에 사용할 문장

> 지도 작성·위치 추정·DWA 주행을 구성하고 전체 통합 테스트를 담당했다. 주행 완료 판정을 정리해 파지 단계로 연결하고, L515의 사용하지 않는 pointcloud 기능을 비활성화해 통합 실행 중 카메라 미송출 문제를 해결했다. 야외에서 주행부터 물품 파지·분류까지 연결해 시연했다.

원본 작업 기록은 로컬 작업관리 폴더에 보존했다. 문제 원인을 확정하지 못한 항목과 최종 시연에서 관찰한 동작을 구분해 설명한다.
